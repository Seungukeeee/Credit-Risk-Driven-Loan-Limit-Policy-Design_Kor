# 신용 리스크 기반 대출 한도 정책 설계
Credit Risk-Driven Loan Limit Policy Design

신용 리스크를 반영해 대출 한도 정책을 설계하고, 정책 타당성을 데이터와 지표로 검증한 프로젝트입니다.

## 문제 정의

대출 심사 실무에서는 고객별 한도를 정해야 하지만, PD 예측만으로는 실제 한도 결정을 내리기 어렵습니다. 기존의 단일 임계값 승인·거절 방식은 한도 차등화가 없어 기회손실과 과다 익스포저를 동시에 초래할 수 있습니다. 그렇기에 예측값을 실제 의사결정으로 연결하는 정책 규칙과 손익 검증 체계가 필요합니다. PD 구간별 차등 한도 정책을 설계하고, **전수 승인(무심사 승인) 가정 대비 정책 적용 후**의 승인율, 부실률, 기대손실 변화로 효과를 검증했습니다.

## 데이터 & 타깃 정의

**데이터**: Home Credit Default Risk(Kaggle) 4개 테이블 — application_train(신청 정보, 307,511건), bureau(외부 신용기관 대출 이력), installments_payments(과거 납부 이력), previous_application(Home Credit 내 이전 대출 이력).

**타겟(TARGET)**: 부도 여부(0/1), 전체 부도율 8.07%.

**분석 단위**: 대출 신청 건이 아닌 고객 단위로 재정의했습니다. 4개 테이블을 SQL(DuckDB CTE)로 고객 단위 집계·통합해, PD 추정과 한도 정책 산정에 함께 쓸 수 있는 하나의 마스터 테이블을 구성했습니다.

**결측·편향 처리**:
- 신용점수 `EXT_SOURCE_1`의 결측률이 56%에 달해 단순 중앙값 대체 시 분포가 심하게 왜곡되는 것을 확인하고, 트리 기반 모델은 결측을 그대로 유지, 로지스틱 회귀는 -1로 대체하는 이원화 전략을 적용했습니다. 결측 여부 자체가 "신용 이력 없음"이라는 정보이므로 별도 플래그 피처로도 남겼습니다.
- 초기 DTI 계산에 오류가 있음을 발견해(`AMT_ANNUITY`, `AMT_INCOME_TOTAL`이 모두 월 단위 값) 계산식을 수정했습니다.
- 절대 시점 정보가 없는 데이터 구조(`DAYS_*` 컬럼이 모두 신청일 기준 상대값)를 확인한 뒤, 전통적 시계열 분할 대신 고객 단위 Stratified Split(80/20)을 채택했습니다.

## 정책 설계 접근법

이 프로젝트의 핵심은 모델 성능이 아니라 PD를 신뢰할 수 있는 정책 입력값으로 만들고, 그 값을 구간별 정책 규칙으로 변환하는 것입니다. 아래 세 단계로 나눠 설계했습니다.

### 1. 정책 변수 검증 (EDA policy design)

DTI, CIR, LTV 등 정책 변수의 정의와 기준치를 데이터로 검증했습니다. 특히 LTV는 비용과 이자 구조를 반영한 정책 지표로 재정의했고, 1.2를 기준으로 부도율이 뚜렷하게 갈리는 변곡점을 확인했습니다. 반면 DTI는 단독 변수로는 설명력이 제한적이어서 보조 지표로 해석했습니다.

### 2. PD 보정 (모델링 + Calibration)

EL(기대손실) = PD × LGD × EAD 계산에 PD가 직접 입력되기 때문에, PD 예측값은 단순한 분류 점수가 아니라 실제 부도율과 정렬된 확률이어야 합니다. 이 신뢰를 확보하기 위해 두 단계를 거쳤습니다.

- **모델 선정**: Logistic Regression을 기준선으로 두고 Random Forest, LightGBM, XGBoost, CatBoost를 결측 처리 방식(NaN 유지 vs -1 대체)별로 비교한 뒤, Optuna 튜닝과 AUC·KS 개선폭, 일반화 성능을 함께 고려해 XGBoost를 최종 채택했습니다.
- **Calibration**: XGBoost 원본 확률의 ECE가 0.31로 높아 순위는 맞지만 절대 확률은 정책에 쓰기 어려웠습니다. Platt Scaling과 Isotonic Regression을 평가셋(calib_eval)에서 비교한 결과, Isotonic이 집계 ECE는 더 낮았지만(0.0032 vs Platt 0.0064) confidence 중상위 구간(0.4~0.8)에서 reliability curve가 비단조적으로 흔들려 적은 표본에 과적합했을 가능성이 컸고, AUC·KS 순위도 Platt(원본과 거의 동일) 대비 소폭 하락했습니다. 곡선 안정성과 순위 보존을 우선해 Platt Scaling을 최종 보정 방법으로 선택했습니다.

이 과정을 통해서 PD값을 EL 계산과 구간 분류의 신뢰 가능한 입력값으로 사용할 수 있었습니다.

### 3. 정책 규칙 설계 (Policy simulation)

회수 이력이 없어 LGD를 직접 추정이 불가능했기 때문에, 바젤 III 비담보 소매 익스포저 기준인 0.55를 기본값으로 두고 0.40과 0.75를 낙관·보수 시나리오로 설정해 불확실성을 정책에 반영했습니다.

보정된 PD를 절대 확률이 아니라 **포트폴리오 평균 부실률 대비 배수**(0.5배/2배/4배 경계)로 4개 tier(저위험/중위험/고위험/거절)로 나눴고, decile 단위로 확인한 실제 부도율이 단조 증가하는 것을 확인해 PD를 tier 설계의 기준 축으로 쓸 수 있음을 검증했습니다. 여기에 LTV(1.2 초과 시 독립적 하향)·CIR(7.5배 초과 시 한도초과 하향, 12배 초과 시 tier 무관 절대 거절)·DTI(중·고위험에 한해 40% 초과 시 보조적 하향)를 각자의 역할에 맞게 결합해 최종 tier를 확정했습니다. 승인 tier의 한도 배수는 LGD 3개 시나리오를 모두 통과해야 하는 보수적 게이트로 결정했으며, 그 결과 저위험은 소득의 3.0배, 중위험은 5.0배까지 승인하고 고위험은 거절로 확정했습니다.

## 평가

정책 설계이므로 단일 지표(AUC)보다 정책 판단에 쓰이는 트레이드오프 지표를 중심으로 평가했습니다.

| 지표 | 적용 전(전수 승인 가정) | 적용 후 | 변화 |
|---|---|---|---|
| 승인율 | 100% | 70.89% | -29.11%p |
| 부실률 | 8.07% | 4.61% | -3.46%p |
| 기대손실(EL, Base 시나리오) | 15.1억 | 5.4억 | **-64.15%** |
| 총 승인 한도 | 367.5억 | 209.3억 | -43.0% |

손실 감소폭(-64%)이 한도 축소폭(-43%)보다 커서, 한도 축소가 무작위가 아니라 실제 고위험 고객군에 집중적으로 작동했음을 시사합니다. 이 효과는 LGD 시나리오와 무관하게 유지됩니다(Optimistic·Base·Conservative 모두 64.1%대로 사실상 동일 — `EL` 계산에서 LGD가 정책 적용 전후 양쪽에 동일하게 곱해지는 상수이기 때문). 다만 한도 축소가 회사 수익(특히 이자 수익)에 미치는 영향은 이번 시뮬레이션에서 다루지 않았으므로, 이 트레이드오프의 최종 타당성은 수익성 지표까지 포함해 별도로 판단해야 합니다.

**모델 성능(참고 지표)**: XGBoost(NaN 유지, 튜닝 후) AUC 0.7689 / KS 0.3969, Logistic Regression 베이스라인 대비 AUC +0.033, PR-AUC +0.047.

**Calibration 검증**: Platt Scaling 적용 후 PD 구간별 예측-실제 부도율 gap 대부분 0.02 이내.

**모니터링(운영 안정성)**: 데이터셋에 절대 시점 정보가 없어 시계열 검증은 불가능했으나, 고객 ID 순서로 train, validation, pseudo production을 구성해 배포 이후 상황을 모사했습니다. 이후 PSI로 입력 분포 변화, PD와 정책 라벨 비중 변화로 의사결정 기준 변화, 지연 라벨 기반 성능으로 실제 품질 저하를 각각 추적하는 3층 모니터링 구조를 설계했고, 모든 지표가 기준선 내에 있어 재학습 트리거가 발동하지 않음을 확인했습니다.

## 결과와 한계

**실험 범위에서 확인된 것**
- PD 기반 구간화 → 정책 규칙 → 시나리오 시뮬레이션까지 이어지는 전체 파이프라인이 일관되게 작동함을 확인했습니다.
- 제안 정책이 전수 승인 대비 부실률과 기대손실을 동시에 낮추되, 손실 감소폭이 한도 축소폭보다 커서 위험이 높은 고객군에 축소가 집중되었음을 수치로 확인했습니다.

**운영 고려가 필요한 부분(실험과 분리)**
- 부도 후 실제 회수 데이터가 없어 LGD를 직접 추정하지 못하고 업계 기준값에 의존했습니다. 실제 운영에서는 회수 이력이 쌓이는 대로 자체 LGD 모델로 대체해야 합니다.
- `DAYS_*` 컬럼이 절대 시점이 아닌 신청일 기준 상대값이라, 엄밀한 시계열 기반 분할과 모니터링에는 한계가 있었습니다. 실제 운영에서는 절대 시점 기준 모니터링으로 교체가 필요합니다.
- 한도 축소가 회사 수익(이자 수익 등)에 미치는 영향은 이번 시뮬레이션에서 다루지 않았습니다. 실제 정책 채택 여부는 수익성 지표까지 포함해 판단해야 합니다.
- 실제 운영 데이터가 아닌 공개 데이터 기반이라 정책 해석에는 가정이 포함됩니다.

**다음 단계**: 절대 시점 정보가 있는 데이터로 확장하거나, 연체 패턴의 시간 가중치 같은 피처 엔지니어링을 통해 모델 성능을 추가로 개선할 수 있습니다.
